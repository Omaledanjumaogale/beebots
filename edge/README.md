# OmieBot edge runtime

Deploy `wrangler deploy --config edge/wrangler.jsonc` from the beebots directory. Set secret bindings with Wrangler secrets; never add keys to vars or browser bundles. Required: EDGE_SERVICE_SECRET, relevant provider keys, ALPACA_API_KEY and ALPACA_SECRET_KEY. ARTIFACTS binds `omiebot-retained-data`; CONTROL is one SQLite Durable Object. No path uses Convex. R2 and Durable Objects still consume their own free allowances and can incur charges above them; they are not zero-storage services.

Authenticated Pages server proxy calls Authorization Bearer EDGE_SERVICE_SECRET. Public GET /health reveals only service and paper state. GET /admin/status returns configuration and counters; PUT /admin/config changes paused, feeds (maximum three), provider permissions, and maxOrderUsd (maximum100). POST /execution/mode accepts paper, rejects live. POST /execution/order accepts id (unique8–48 chars), symbol, side, notional. POST /execution/reconcile accepts id, reads broker status without resubmitting. Pending unknown orders remain pending and require reconciliation; no automatic retries can duplicate submission. Daily cap10 and order cap25USD default. Paper Alpaca endpoint is hardcoded. Browser callers must never receive the service secret. Owner role verification belongs to Pages proxy.

Provider keys alone do not establish redistribution or retention rights. All providers start disabled; owner confirms enabled and retentionAllowed permissions. Endpoint allowlists exclude arbitrary URLs; unknown Finnhub/Massive/Agnes/Workers AI budgets remain zero. Twelve8/min800/day and Alpha25/day are verified against https://support.twelvedata.com/en/articles/5615854-credits and https://www.alphavantage.co/support/ . FMP250/day512MB/rolling30days and Marketstack100/month are owner supplied caps. Runtime retains10% headroom except1/min policies; failed calls consume reservation; each request conservatively reserves1MB. No key rotation or quota bypass. Counters use UTC windows; bandwidth uses rolling30days. All calls elsewhere in a provider account consume allowance too: dedicate keys/accounts or reduce caps before enabling. No automatic provider fallback multiplication.

GET /market?provider=twelvedata&endpoint=time_series&symbol=BTC/USD fetches once per5min cache window; budget refusal means abstain. Data is cached only with retentionAllowed. Five-minute cron fetches only explicitly configured active feeds when unpaused; crypto open continuously, forex conservative Monday–Friday before Friday20UTC, no equity adapter yet. Autonomous simulated paper trading uses confirmed closed OKX5min bars, no data older15minutes, never unconfirmed candles. Drift uses momentum, Rebound uses mean reversion, Breaker uses breakout. Enable each using config bees:[{id:'drift',enabled:true},...]. Each bot/instrument has10000 simulated starting cash,25USD entries, no shorts/leverage,2%stop4%takeprofit,4fills/day cap and10bp fees+10bp slippage each side. Status returns per-bot balances, positions and decisions. R2 paper/day/event files record events. Live exchange orders and Alpaca paper broker orders require explicit authenticated requests; autonomous simulation does not submit brokerage orders. No guaranteed-profit claim.

Daily cron `0 3 * * *` is04:00 Africa/Lagos. It reads only R2 datasets/{drift|rebound|breaker}.json arrays of `{time:unixMilliseconds,close:number}` containing closed bars; no provider/LLM calls. Each dataset needs1200–5000 bars, sorted without duplicates. Bounded10-epoch logistic candidate on the latest2000bars uses past1/5/20-bar returns, chronological70/30 split, one-label purge, train-only scaling, Brier improvement>.005, positive net improvement>.01 and30 out-of-sample trades at40bp round-trip fee/slippage cost. Passing writes challenger.json and status shadow-ready, never activates for trading without independent forward validation. Latest result in training/{bee}/latest.json. Three baseline bees share this experimental candidate family; seventeen additional roles remain research. This is neither a full walk-forward certification nor evidence of trading profitability. Primary configured feed appends deduplicated closed bars for enabled bees when retention permission is enabled. Primary training instrument is frozen in durable configuration; changing it requires a separate hive to prevent mixed data. PUT /admin/datasets accepts {bee,bars,retentionRightsConfirmed:true} at most5000 bars/1MB. GET /admin/training returns latest outcomes. R2 lifecycle should expire training history/raw datasets under owner data licenses.

POST /auth/rate accepts key as64-character SHA256 digest, reserves5attempts/15minutes per digest. Pages must hash IP with a server secret, enforce owner auth for admin endpoints and fail closed if runtime unavailable. Login limiter uses durable storage, expired keys removed daily. An attacker must never receive EDGE_SERVICE_SECRET.

Training computation runs in isolated training:bee Durable Object instances, not the ordinary Worker invocation. Cloudflare documents30seconds default CPU per Durable Object invocation at https://developers.cloudflare.com/durable-objects/platform/limits/ ; the ordinary Workers Free10ms CPU limit must not be mistaken for adequate training capacity. Each job is capped2000bars10epochs; cron only dispatches jobs. No plan upgrade is performed. Broker network requests use a separate broker Durable Object, preventing their latency from blocking the hive login/quota object.

All R2 writes reserve byte deltas through a separate storage-budget Durable Object before writing. Dedicated bucket cap8GB,10000objects,1MB/object; failed writes conservatively retain reservations. Overwrites replace prior byte reservations. This tracks writes through this runtime only, excludes pre-existing/external objects and other Cloudflare services, and cannot guarantee shared account free allowances. /admin/status exposes storage usage and scope. Aggregate OKX ticker cache60seconds, individual ticker10seconds, candles5minutes; provider counters count each upstream cache miss including failures. Free quotas depend on other applications sharing the same account.
